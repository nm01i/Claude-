# Case study research: index

Research stage for the five portfolio projects. **No website code was changed.** The implementation plan is a proposal only
(`content-model-proposal.md`).

| File | Content |
|---|---|
| `00-source-inventory.md` | Every supplied source, what could be opened, what could not, and why |
| `gift-match.md` | Full research report, design system, asset inventory, Behance-style outline and website copy (the only project whose source could be inspected in depth) |
| `muza.md`, `triply.md`, `lumie.md`, `saas.md` | What is known, what is blocked, what is needed. Deliberately short: no source evidence yet |

| `content-model-proposal.md` | Proposed data model, GIFT MATCH entry filled in, implementation plan |
| `questions.md` | Prioritized questions that need your input |

## Labels used everywhere

* **[V] Verified**: read directly from a source file (Figma node text, node properties, generated style values) or stated by you.
* **[I] Interpretation**: a reasonable design reading of verified material. Not a documented fact.
* **[R] Recommendation**: something to do or add.
* **[C] Confirm**: needs your answer before it can be published.
* **[E] Estimated**: read from a screenshot, not measured. Never used as an exact value.

Russian source copy is translated into English by me; the original is kept next to it where it matters.

Additional labels used in the MUZA and TRIPLY reports: **[S]** verified in the project's source code or repo assets, **[L]** verified on the live site (none yet), **[U]** stated by you.
